# SF2e Missing Tech Pets

**Версия 0.12.0.** Роботизированные компаньоны и нативные фамильяры Tech Core: предметы и инструменты управления ими для Foundry VTT v14 / Starfinder 2e. 

> Проверены исходники, данные, сборка компендиумов и сценарии с mocks. Настоящий Foundry v14 с игровым миром для проверки не запускался. Наличие описания действия не означает автоматического выполнения его эффекта.

## Совместимость и обязательная зависимость

- Foundry VTT **v14**, минимум **14.361**. Поля minimum/verified/maximum ограничивают поддержку v14. `verified: "14"` — декларация совместимости, не отчёт об игровом тестировании конкретной сборки.
- Starfinder 2e **sf2e 1.6.0+**.
- **PF2e Companion Compendia (`pf2e-animal-companions`) 7.6.3+ обязателен и должен быть активен.** Зависимость находится в `relationships.requires`. Без неё основной интерфейс и интеграция не запускаются.
- Изучены исходники зависимости, её SF2e-предметы, выпуск 7.7.3 и исправление SF2e-ссылок в 7.6.3. Минимальная версия зависимости не повышена.

Манифест зависимости: https://github.com/TikaelSol/PF2e-Animal-Companions/releases/latest/download/module.json

## Установка и обновление

1. Сделайте резервную копию мира, актёров и старой папки модуля. Для первой проверки используйте копию мира.
2. При выключенном Foundry распакуйте ZIP в `Data/modules/`. Получится `Data/modules/sf2e-missing-tech-pets/module.json`, без лишней вложенности.
3. При обновлении замените папку старого модуля целиком; не смешивайте файлы двух версий.
4. Установите/обновите обязательную зависимость и активируйте оба модуля в мире SF2e.
5. Откройте меню заголовка листа персонажа и выберите **Tech Pets**. Настройка мира позволяет скрыть этот пункт.

В архив уже включены готовые **LevelDB-компендиумы**. Node.js и сборка для ручной установки не нужны.

## Фамильяры на листе персонажа

В SF2e 1.6.0 уже есть нативный тип актора `familiar`, системный лист, `system.master.id` / `system.master.ability`, наследование характеристик владельца и обработка Rule Elements. В 0.12.0 добавлены недостающие точки входа и содержимое Tech Core; движок PF2e не копируется и расчёты не дублируются.

1. В меню заголовка листа **персонажа** выберите **«Фамильяры»**. Тот же пункт доступен на системном листе фамильяра; каталог способностей в Tech Pets открывает эту панель.
2. Создайте нативного фамильяра либо выберите существующего актора типа `familiar` без другого владельца. Нажмите «Связать / сохранить характеристику» и выберите характеристику владельца. Права при создании копируются с владельца; отсутствие права создавать Actor обрабатывает Foundry, тогда попросите ведущего создать актора.
3. Откройте системный лист фамильяра и проверьте характеристики. Модуль не выдаёт владельцу фит, не определяет наличие права на фамильяра и не подменяет системные методы.
4. Выберите ежедневный набор и сохраните. Положительный `system.attributes.familiarAbilities.value` владельца используется как лимит; при отсутствии значения берутся **2 способности** из правил фамильяра. Для домашних правил/неавтоматизированных фитов можно задать явный лимит; пустое поле возвращает автоматический. Это лимит панели: она не создаёт фиты или системный счётчик владельца; если он равен 0, нативный лист может показывать 0 до добавления соответствующего системного предмета.
5. Отметьте установленные врождённые способности и отдельно сохраните эти отметки. Они учитываются в лимите и не снимаются ежедневным выбором. Пометки не назначаются по картинке/виду существа: это явное решение пользователя.

Поддерживаются поиск, описания, открытие установленного Item, отправка его в чат и переход к системному листу. Связи переживают перезапуск благодаря нативным данным Actor. Занятый фамильяр не перепривязывается молча. Если с владельцем уже связаны несколько фамильяров, выберите нужного для просмотра и исправьте лишние связи на системных листах.

### Способности Tech Core

`familiar-abilities` содержит **38 самостоятельных SF2e Action Items**, категории Pet / Familiar / Master, с полными английскими описаниями. Это способности, а не 38 обычных фитов персонажа. Они поставляются вместе с модулем, не требуют поиска одноимённых PF2e Items и имеют стабильные ID, slugs и sourceId. Все находятся на фамильяре; эффекты категории Master на владельца сами по себе не переносятся.

**Rule Elements подготовлены для 10 пассивных способностей:** Burrower (burrow 5), Climber (climb 25), Flier (fly 25), Darkvision, Echolocation (precise 20), Scent (imprecise 30), Tough (+2 HP за уровень), Dragon, Fungus и Plant (замена animal на соответствующий trait). Схемы BaseSpeed, Sense, FlatModifier и ActorTraits сверены по SF2e 1.6.0; фактическая подготовка в игровом мире ещё не проверена.

**Остальные 28 способностей — правила для ручного применения.** В частности, Construct не выдаёт иммунитеты автоматически; Elemental, Resistance, Skilled, Fast Movement и Damage Avoidance требуют ручной настройки вариантов/механики. Способности владельца не изменяют его ресурсы, заклинания, фокус или HP автоматически. Familiar Focus оформлен с ценой 2 действия, но не списывает их и не восстанавливает фокус программно.

Проверяются необходимые способности у Construct, Elemental, Kinspeech, Master's Form, Plant Form, Toolbearer и уровень владельца у Kinspeech. Все прочие предпосылки, варианты выбора, языки, наличие заклинаний и разрешённость эффектов проверяйте по описанию. Повторяемый Skilled с разными навыками пока добавляется штатным drag-and-drop и настраивается вручную; панель выбирает одну копию. Импорт через API/браузер направляет familiar-действия на нативного фамильяра, не на character-робота. Штатное перетаскивание остаётся пользовательским действием; не бросайте эти Items на робота или владельца.

При ежедневной смене удаляются только неизменённые Items этой панели и этого владельца. Ручные, сторонние, изменённые и врождённые Items сохраняются и учитываются в лимите. Их удаление выполняется осознанно на системном листе. Повторная/параллельная синхронизация не создаёт копии. Отказ загрузки каталога не очищает прежние способности.

### Переход со старого каталога фамильяров

Старые `robot.familiarAbilities` не стираются и не переносятся без подтверждения. Кнопка «Отметить прежние записи профиля» только отмечает распознанные записи; затем сохраните ежедневный набор на настоящем фамильяре. Старые предметы на character-роботе не удаляются. **Старая роботизированная синхронизация больше не создаёт familiar Items на character**: такие записи отмечаются как пропущенные, а уже применённые остаются защищёнными. После резервного копирования проверьте и вручную уберите ненужные старые эффекты, чтобы не оставить их одновременно на роботе и фамильяре.

AON на момент сверки присоединяет текст Vital Bond к концу Spell Delivery. В каталоге он выделен в существующую отдельную запись Vital Bond без придуманной механики; источник и оговорка сохранены.

## Владелец и роботизированный компаньон

1. Создайте владельца и **отдельного актора типа character** для робота, не NPC.
2. На листе владельца откройте Tech Pets и выберите компаньона. Оба актора должны быть доступны для редактирования.
3. Выберите шасси в каталоге. Для шасси с двумя допустимыми размерами выберите размер.
4. Примените выбранные правила и проверьте результат на листе компаньона.
5. Укажите фактическую ступень робота. **Advanced/Superior** разрешает выдачу манёвра, но переключатель **не выдаёт фиты ступени и не повышает характеристики**.

Связь сохраняется в обе стороны. Self-link, циклы, цепочки компаньонов и присвоение занятого компаньона запрещены. При открытии Tech Pets с привязанного компаньона используется профиль владельца.

Шасси из собственного компендиума можно перенести штатным drag-and-drop на отдельный character-лист. Без владельца такой актёр учитывается как самостоятельный компаньон, а не как ссылка на самого себя. Происхождение из стороннего пака остаётся пользовательским: модуль не присваивает себе право его перезаписывать.

На акторе нельзя иметь два ancestry. Конфликтующее происхождение модуль **не удаляет**: сначала проверьте его вручную.

## Собственные компендиумы

| Пак | Содержимое |
| --- | --- |
| `robot-chassis` | 5 ancestry: Agile, Imitator, Powerful, Surveillance, Tank |
| `robot-advanced-maneuvers` | 5 action: Surgical Strike, Disturbing Display, Hydraulic Flipper, Blinding Spotlight, Ram Slam |
| `robot-support` | 5 отдельных action с Support Benefit соответствующего шасси |
| `familiar-abilities` | 38 action: способности Pet / Familiar / Master из Tech Core |

Шасси задают нативные поля ancestry и Rule Elements: базовые модификаторы, HP, размер, скорости, чувства, обучение навыкам, traits и Strikes. Базовый класс компаньона выдаётся через GrantItem из **SF2e**-пака зависимости:

`Compendium.pf2e-animal-companions.sf-AC-Features.Item.KKOgokqHa7RjVDN6`

Без доступного класса новое неполное шасси не создаётся; прежние предметы сохраняются и показывается предупреждение.

Поддержка выдаётся вместе с шасси, манёвр — на Advanced/Superior. Действия можно открыть на листе и отправить в чат кнопками Tech Pets.

**Манёвры и поддержка разыгрываются вручную:** модуль не выполняет за них Strikes, Demoralize, спасброски, перемещение, длительности и условное наложение состояний. Ссылки на состояния в текстах не означают их автоматического применения.

## Imitator Chassis

До настройки у Imitator **нет сгенерированного имитируемого Strike**. Medium / 25 футов в исходном ancestry — временные значения, не выбранный вид существа; перед игрой настройте шасси.

1. Выберите Imitator, затем «Настроить Imitator».
2. Найдите живое происхождение из `sf2e.ancestries` либо животное из SF2e-пака происхождений Companion Compendia.
3. Источник должен явно задавать размер, скорости и хотя бы одну безусловную рукопашную безоружную атаку.
4. Выберите конкретную атаку и подтвердите.

Сохраняются UUID/название источника, размер, скорости и выбранная атака. Робот получает **1d4 выбранного типа урона**, unarmed, agile, finesse; чужие бонусы, черты и Rule Elements не копируются. Выбор переживает повторную синхронизацию.

Условные, вычисляемые, ranged-атаки и источники с неоднозначным размером отклоняются. Не все живые происхождения содержат подходящий Strike, поэтому **не все виды доступны**. Произвольные NPC и копирование всех особенностей существа не поддерживаются.

## Кастомизации, способности и слоты

- Сохранены 36 кастомизаций, поиск и браузер компендиумов; 38 способностей фамильяра расширены до самостоятельных Items и отдельной панели.
- Используются совместимые Item-паки SF2e. PF2e-паки, чужая явно указанная система, PF2e-ссылки в Rules и неизвестные установленной системе ключи Rule Elements отклоняются.
- Точный slug/identifier ищется во всех разрешённых паках **до** поиска по имени. Проверяется тип Item. Источник копируется с Rules и `flags.core.sourceId`.
- Неопределённые сторонние паки без данных о системе не считаются безопасными автоматически.
- При отсутствии источника запись остаётся в профиле; эффекты не выдумываются. Ранее применённый предмет не удаляется из-за временной недоступности источника.
- Ручная запись — только заметка и учёт слотов, не работающий Rule Element.
- Дополнительные слоты задаются точным slug в настройке slotGrantRules или флагом Item `flags.sf2e-missing-tech-pets.modificationSlots`.
- Общий slug customization сам по себе слотов не даёт. Дубли источника не начисляют слоты повторно; правило и флаг одного Item не суммируются.
- Выборы сверх доступных слотов сохраняются, но пропускаются при синхронизации. Ступень в каталоге не заменяет проверки всех игровых prerequisites.

## API

```js
const api = game.modules.get("sf2e-missing-tech-pets").api;
api.open(actor);
await api.linkActors(owner, companion);
await api.syncAutomation(owner);
```

Сохранены `open(actor?)`, `searchFamiliarItems(actor?, query?)`, `getRobotData(actor)`, `setRobotData(actor, data)`, `getModificationSlots(actor)`, `getLinkedCompanion(actor)`, `resolveImportTarget(actor, item)`, `addCompendiumItem(actor, item)`, `syncAutomation(actor)`, `registerSlotGrant(slug, slots = 1)`, `openPack(key, actor?)`.

Добавлен `linkActors(owner, companion)`; null вместо companion разрывает связь. setRobotData проверяет ссылки; занятый компаньон сначала освобождается от старой связи. syncAutomation возвращает `{ applied, skipped, reason? }`: **applied — число применённых/сохранённых Items, не автоматически исполненных игровых эффектов**.

Дополнительный API фамильяров (отдельно от связи роботов):

```js
await api.openFamiliar(owner); // также принимает familiar
const familiar = await api.createFamiliar(owner, "wis");
await api.linkFamiliar(owner, familiar, "wis");
await api.syncFamiliarAbilities(owner, familiar, ["flier", "tough"]);
```

`createFamiliar` требует отсутствие другого связанного фамильяра; не выдаёт фит владельцу. `linkFamiliar` не захватывает занятого актора. `syncFamiliarAbilities` возвращает `{created, removed, protected}` и отклоняет невалидный набор с локализованной ошибкой. Эти методы также требуют активную обязательную зависимость.

## Разработка и проверки

Код запускается как ES modules без сборки JS. Для разработки: Node.js 22+ и `npm install`.

```sh
npm run build:packs
npm run check
npm test
```

`data/robot-chassis.json` и `scripts/item-sources.mjs` — источник предметов. Для фамильяров источники — `data/familiar-abilities.json` и `scripts/familiar-sources.mjs`. Сборка обновляет четыре packs/src/, текстовые .db и готовые LevelDB-каталоги. Манифест загружает **LevelDB**; .db оставлены как проверяемые текстовые снимки, не рабочие пути v14.

Воспроизводимость проверяется по документам/ID, не двоичному совпадению служебных файлов LevelDB. Сборщик сначала компилирует во временную папку и извлекает документы обратно, затем заменяет свой готовый пак.

Подробности: [аудит](docs/AUDIT.md), [проверки и игровой чек-лист](docs/TEST-REPORT.md), [изменения](CHANGELOG.md).
