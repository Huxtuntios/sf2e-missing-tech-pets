# SF2e Missing Tech Pets

## Описания, бонусные способности и обновления

Раскройте запись в **«Улучшениях робота»** или каталоге инструментов: описание игровых правил читается внутри модуля. Ссылка на Архивы Нефиса служит дополнительным источником, а не заменяет описание.

Выбранные кастомизации — нативные **feat** Items с категорией **bonus**, видимые в **«Бонусных способностях»** на `character`-листе самого компаньона. Владельцу они автоматически не выдаются. Сохраняются пассивные Rules, стоимость действий и UUID источников; вторые копии Actions/Rule Elements не создаются. Способности фамильяра остаются действиями на акторе `familiar`, у которого нет группы бонусных черт персонажа. Поддержка и продвинутые манёвры тоже остаются действиями.

При сохранении текущего набора неизменённая кастомизация, созданная модулем в старом формате Action, заменяется бонусным feat. Сначала создаётся замена, только затем удаляется прежний Item. Допустимый выбор Armored Plates переносится. При смене типа меняется ID embedded Item: при необходимости обновите сохранённые ярлыки на предмет актора; ID компендиума остаются прежними. Ручные и изменённые копии не преобразуются скрытно и не дублируются. Защищённый старый Action и его источник проверьте перед осознанной заменой.

Постоянный адрес установки и обновления:

```text
https://github.com/Huxtuntios/sf2e-missing-tech-pets/releases/latest/download/module.json
```

Foundry видит новую версию только после публикации публичного GitHub-релиза с обновлёнными Assets. Коммит файлов или полученный ZIP сами по себе ничего не публикуют. Опубликуйте **v0.16.2** как обычный **Latest**-релиз, не draft и не prerelease. Workflow теперь проверяет не только загруженные Assets, но и версию, которую возвращает публичный latest-манифест. Если старая установка использует манифест отдельного тега, один раз переустановите модуль по постоянному адресу выше. Подробнее — [в инструкции](docs/RELEASING.md).


## Собственные предметы кастомизаций робота

Все **36 кастомизаций робота** теперь имеют собственные SF2e бонусные feat Items в компендиуме `robot-customizations`. Сохранение выбора не зависит от поиска одноимённого предмета в стороннем паке или среди способностей фамильяра.

- **Пассивные Rule Elements (10):** Aquatic Adaptation, Armored Plates, Climber, Flier, Burrower, Nightvision Sensors, Olfactory Receptors, Echolocation, Hardened Chassis и Speedster.
- **Ручное применение (26):** остальные кастомизации содержат описания и ссылки на правила, без выдуманных числовых эффектов. Например, Speakers позволяет говорить через робота и не требует искусственного бонуса. В каталоге видна разница; при синхронизации ручные применения перечисляются информационным сообщением, а не ошибкой отсутствующего источника.
- **Armored Plates:** нативный ChoiceSet предлагает +1 либо +2 для действительно Superior-компаньона. Выберите подходящий бонус при добавлении Item; при развитии робота измените выбор в его Rule Element. Лимит ступени каталога сам по себе не повышает компаньона и не назначает этот бонус.
- Сохраняются стоимость слотов, ограничения ступени и игровые требования. Наличие Item не означает автоматического исполнения всех активных эффектов его описания.

**После обновления:** перезагрузите мир, откройте **Способности → Улучшения робота** и повторно сохраните текущий набор, не меняя выборы профиля. Неизменённая кастомизация, ранее созданная модулем с неверным источником, исправляется безопасно; старый Action заменяется бонусным feat только после создания замены. Ручные и отредактированные предметы сохраняются; защищённую старую копию проверяйте самостоятельно, не удаляйте Items массово. Точная копия собственной кастомизации, перенесённая штатным drag-and-drop, не дублируется и не присваивается для автоматического удаления.

Правила: [Robot Customizations — Archives of Nethys](https://2e.aonsrd.com/companions/types/robot/customizations).

## Необязательная интеграция с PF2e Dailies

**PF2e Dailies (`pf2e-dailies`) 4.23.1+ необязателен. PF2e Companion Compendia 7.6.3+ остаётся обязательной зависимостью.** Используется публичный `game.dailies.api.registerCustomDailies`, без подмены методов и изменения API Dailies. Контракт API сверен с исходниками Dailies 4.23.1.

1. Включите Dailies и перезагрузите мир. Свяжите одного нативного актора `familiar` с владельцем типа `character`; нужны права владельца на обоих.
2. Закройте открытые окна ежедневной подготовки. На листе фамильяра раскройте **Выбор способностей фамильяра** и нажмите **Готовить в Dailies**. Те же настройки доступны в инструменте управления фамильяром.
3. Подключение отключает **только стандартный набор фамильяра Dailies у этого владельца** и добавляет набор **Способности фамильяра Tech Core**. Другие подготовки и владельцы не затрагиваются. Не включайте стандартный набор повторно при подключённой интеграции.
4. Нажмите **Открыть Dailies** или используйте штатный вход Dailies на листе владельца. Выберите способности и завершите подготовку там. Локальный редактор ежедневного набора скрывается; новые кнопки в заголовке персонажа не добавляются.
5. Перед следующей подготовкой используйте обычный отдых Dailies. Обработчик отдыха снимает только неизменённые ежедневные Items, созданные нашим модулем. Врождённые, ручные, сторонние и изменённые предметы защищены и учитываются в лимите.
6. Кнопка **Отключить интеграцию Dailies** восстанавливает прежнюю настройку стандартного набора, если вы не поменяли её вручную. Предметы фамильяра сохраняются, локальный выбор возвращается. При отсутствии Dailies или несовместимом API локальный редактор остаётся доступен.

В наборе доступны 38 способностей Tech Core из собственного компендиума модуля. Проверяются лимит и известные требования, предотвращаются дубликаты, сохраняются UUID источников. Защищённые способности показаны отдельно и занимают места в лимите. Dailies запоминает прошлый выбор; пустые места допустимы. Если остались временные способности стандартного набора Dailies, сначала выполните отдых через Dailies: наш модуль не присваивает и не удаляет эти чужие Items.

Интеграция **не** автоматизирует все активные эффекты описаний, не выдаёт фит фамильяра, не реализует повторяемые варианты Skilled и не заменяет системный расчёт характеристик. Прежние границы Rule Elements и ручного применения сохраняются. Другие сторонние ежедневные наборы, меняющие способности этого фамильяра, отключаются отдельно. Ошибка нашего набора не откатывает прочие подготовки Dailies. После смены настроек закройте и заново откройте Dailies; не используйте старое окно подготовки.

Референс: [PF2e Dailies](https://github.com/reonZ/pf2e-dailies), [публичный API](https://github.com/reonZ/pf2e-dailies/blob/master/src/main.ts), [стандартный набор фамильяра](https://github.com/reonZ/pf2e-dailies/blob/master/src/data/familiar.ts).


## Способности на листе питомца

Дополнительные кнопки в заголовках листов убраны. Для создания, связи акторов, справочника источников и дополнительных инструментов откройте **Настройки → Настройки модуля → SF2e Missing Tech Pets → Открыть инструменты** и выберите актора. Публичный API сохранён.

- **Робот-компаньон:** на вкладке **Способности / Feats** самого компаньона раскройте **«Улучшения робота»**. Видны текущие выборы, все 36 записей каталога, ступени и количество повторяемых улучшений. Измените набор и нажмите **«Сохранить выбор»**. Проверяются слоты и доступная ступень. Ручные и неизвестные старые записи сохраняются; предметы-источники включены в модуль; записи с ручным применением не выдают выдуманных эффектов.
- **Нативный фамильяр:** в существующем разделе **Способности** раскройте **«Выбор способностей фамильяра»**. Доступны 38 способностей, описания и смена ежедневного набора. Врождённые, вручную добавленные и изменённые предметы защищены от удаления. Установленные Items остаются в системном списке.
- Панели находятся на самом компаньоне/фамильяре, а не на каждом персонаже-владельце. Сохранять может пользователь с правами на обоих связанных акторов. Если данные изменились во время выбора, переоткройте лист — более новые данные не перезаписываются.
- Шасси скрыты в нативном выборе родословных персонажа, включая world-копии с сохранённым происхождением. Перетащите шасси из **Robot Chassis (Tech Core)** на отдельный лист компаньона типа `character`, как в Companion Compendia. Каталог шасси теперь справочный, без выдачи кнопкой выбора. Существующие шасси и данные пользователя сохраняются.
- Оставшиеся окна инструментов ограничены размером экрана, содержимое прокручивается. Каталоги имеют собственную прокрутку и поиск.

После обновления перезагрузите страницу мира для обновления переводов. У уже импортированных шасси сохранённое изображение остаётся прежним: выберите соответствующий SVG из `modules/sf2e-missing-tech-pets/assets/icons/` через выбор изображения предмета. Пользовательские изображения не перезаписываются.

## Источники компаньонов и Pet (0.14)

Откройте **Техно-питомцы → Источники компаньонов и Pet** либо одноимённую кнопку в **Фамильярах**. Справочник различает выдачу существа, его развитие и уход. Учтены 13 источников SF2e: Familiar, Enhanced Familiar, Incredible Familiar, Pet, Drone, Tactical/Advanced/Superior Drone, четыре ступени Customization и Devoted Pet Owner. Предмет можно открыть с листа либо по точному системному UUID. Черты не выдаются и не переобучаются автоматически.

- Лимит фамильяра — наибольшее из **2/4/6** по полученным чертам и положительного системного значения, а не их сумма. Ручной лимит приоритетен. Сам класс техноманта фамильяра не выдаёт. Для недостающих исходных черт выводятся напоминания, а не создаются предметы.
- Для взаимно связанного дрона каждая полученная Tactical/Advanced/Superior Drone даёт один слот от развития и один дополнительный от черты, ограниченные соответствующей ступенью. Каждая ступень Customization даёт один целевой слот. Сохранены два дополнительных коммерческих слота Drone. Дубликаты импорта не увеличивают число выборов.
- Повторяемые Customization по умолчанию учитываются один раз. Поле **Подтверждённых выборов** (1–3) предназначено только для действительно повторных выборов черты. Повтор Superior Drone не даёт дополнительных кастомизаций. Явные правила слотов/флаги предметов приоритетны и повторно не начисляются. После сохранения переоткройте Tech Pets и синхронизируйте.
- Показанная ступень дрона — справочная. **Предел ступени**, предметы развития, выбор burly/deft/специализации и характеристики контролируются игроком/ведущим. Целевые слоты нельзя потратить на ручную заметку или другую ступень. Сохранённые записи и посторонние Items не удаляются.
- **Pet** ведётся отдельно: имя, активность и ровно две разные способности категории Pet. Профиль хранится на владельце, не создаёт актора, черту, ОЗ/КД, действия или Rule Elements. В справке указаны характеристики Pet и запрет Ударов. Врождённые способности, замена/переобучение контролируются вручную; иные способности фамильяра не предлагаются без отдельного согласования с ведущим.
- Активный профиль Pet блокирует создание/связь фамильяра средствами модуля; связанный фамильяр блокирует активацию Pet. Конфликтующие старые данные не удаляются. Необходимое переобучение Pet не выполняется молча.
- Для животных-компаньонов сохранены SF2e-паки зависимости и прежние инструменты связи/импорта. Модуль не выводит право на животное-компаньона только из класса, происхождения или похожего имени. По правилам животное и робот-компаньон взаимоисключающие, но совместимы с фамильяром либо Pet. Межмодульные связи всех акторов автоматически не сканируются — ограничение показано как напоминание.
- Купленные миниботы, курьерские дроны и турели не считаются источниками компаньона/фамильяра. Devoted Pet Owner улучшает лечение, не выдаёт существо; лечение и иммунитет робота применяются вручную.

Справочник — курируемая интеграция SF2e, **не полный импортёр классов, архетипов и черт происхождения PF2e**. Для Pet приведена ссылка AON, но не выдуман системный UUID. Полный автоматический лист Pet, поиск всех источников животных-компаньонов, проверка всех требований и автоматическое применение характеристик развития не реализованы.

Подробнее: [источники и границы](docs/COMPANION-SOURCES.md).

## Установка и обновление

### Установка через Foundry

Сначала установите обязательную зависимость. В **Add-on Modules → Install Module** вставьте:

```text
https://github.com/Huxtuntios/sf2e-missing-tech-pets/releases/latest/download/module.json
```

Адрес заработает после публикации первого обычного релиза и успешного завершения workflow **Release**. Для pre-release используйте ссылку на module.json конкретного тега.

### Ручная установка

Релизный **module.zip** распаковывается **внутрь** заранее созданной папки `Data/modules/sf2e-missing-tech-pets/`: module.json лежит в корне архива. Автоматические архивы GitHub **Source code** не являются установочным пакетом.


1. Сделайте резервную копию мира, актёров и старой папки модуля. Для первой проверки используйте копию мира.
2. При выключенном Foundry распакуйте установочный архив по соответствующей инструкции выше. Должен получиться путь `Data/modules/sf2e-missing-tech-pets/module.json`, без лишней вложенности.
3. При обновлении замените папку старого модуля целиком; не смешивайте файлы двух версий.
4. Установите/обновите обязательную зависимость и активируйте оба модуля в мире SF2e.
5. В настройках модуля нажмите **«Открыть инструменты»**, выберите актора и **«Техно-питомцы»** либо **«Фамильяры»**. Кнопок в заголовках листов больше нет.

В архив уже включены готовые **LevelDB-компендиумы**. Node.js и сборка для ручной установки не нужны.

## Фамильяры на листе персонажа

В SF2e 1.6.0 уже есть нативный тип актора `familiar`, системный лист, `system.master.id` / `system.master.ability`, наследование характеристик владельца и обработка Rule Elements. Панель добавляет недостающие точки входа и содержимое Tech Core; движок PF2e не копируется и расчёты не дублируются.

1. Для первоначальной настройки откройте **Настройки модуля → SF2e Missing Tech Pets → Открыть инструменты**, выберите владельца и **«Фамильяры»**. После связи меняйте ежедневный набор прямо в разделе **Способности** листа фамильяра. Дополнительный менеджер остаётся доступен из настроек.
2. Создайте нативного фамильяра либо выберите существующего актора типа `familiar` без другого владельца. Нажмите «Связать / сохранить характеристику» и выберите характеристику владельца. Права при создании копируются с владельца; отсутствие права создавать Actor обрабатывает Foundry, тогда попросите ведущего создать актора.
3. Откройте системный лист фамильяра и проверьте характеристики. Модуль не выдаёт владельцу фит, не определяет наличие права на фамильяра и не подменяет системные методы.
4. Выберите ежедневный набор и сохраните. Положительный `system.attributes.familiarAbilities.value` владельца используется как лимит; при отсутствии значения берутся **2 способности** из правил фамильяра. Для домашних правил/неавтоматизированных фитов можно задать явный лимит; пустое поле возвращает автоматический. Это лимит панели: она не создаёт фиты или системный счётчик владельца; если он равен 0, нативный лист может показывать 0 до добавления соответствующего системного предмета.
5. Отметьте установленные врождённые способности и отдельно сохраните эти отметки. Они учитываются в лимите и не снимаются ежедневным выбором. Пометки не назначаются по картинке/виду существа: это явное решение пользователя.

Поддерживаются поиск, описания, открытие установленного Item, отправка его в чат и переход к системному листу. Связи переживают перезапуск благодаря нативным данным Actor. Занятый фамильяр не перепривязывается молча. Если с владельцем уже связаны несколько фамильяров, выберите нужного для просмотра и исправьте лишние связи на системных листах.

### Способности Tech Core

`familiar-abilities` содержит **38 самостоятельных SF2e Action Items**, категории Pet / Familiar / Master, с полными английскими описаниями. Это способности, а не 38 обычных фитов персонажа. Они поставляются вместе с модулем, не требуют поиска одноимённых PF2e Items и имеют стабильные ID, slugs и sourceId. Все находятся на фамильяре; эффекты категории Master на владельца сами по себе не переносятся.

**Rule Elements подготовлены для 10 пассивных способностей:** Burrower (burrow 5), Climber (climb 25), Flier (fly 25), Darkvision, Echolocation (precise 20), Scent (imprecise 30), Tough (+2 HP за уровень), Dragon, Fungus и Plant (замена animal на соответствующий trait). Схемы BaseSpeed, Sense, FlatModifier и ActorTraits сверены по SF2e 1.6.0.

**Остальные 28 способностей — правила для ручного применения.** В частности, Construct не выдаёт иммунитеты автоматически; Elemental, Resistance, Skilled, Fast Movement и Damage Avoidance требуют ручной настройки вариантов/механики. Способности владельца не изменяют его ресурсы, заклинания, фокус или HP автоматически. Familiar Focus оформлен с ценой 2 действия, но не списывает их и не восстанавливает фокус программно.

Проверяются необходимые способности у Construct, Elemental, Kinspeech, Master's Form, Plant Form, Toolbearer и уровень владельца у Kinspeech. Все прочие предпосылки, варианты выбора, языки, наличие заклинаний и разрешённость эффектов проверяйте по описанию. Повторяемый Skilled с разными навыками пока добавляется штатным drag-and-drop и настраивается вручную; панель выбирает одну копию. Импорт через API/браузер направляет familiar-действия на нативного фамильяра, не на character-робота. Штатное перетаскивание остаётся пользовательским действием; не бросайте эти Items на робота или владельца.

При ежедневной смене удаляются только неизменённые Items этой панели и этого владельца. Ручные, сторонние, изменённые и врождённые Items сохраняются и учитываются в лимите. Их удаление выполняется осознанно на системном листе. Повторная/параллельная синхронизация не создаёт копии. Отказ загрузки каталога не очищает прежние способности.

### Переход со старого каталога фамильяров

Старые `robot.familiarAbilities` не стираются и не переносятся без подтверждения. Кнопка «Отметить прежние записи профиля» только отмечает распознанные записи; затем сохраните ежедневный набор на настоящем фамильяре. Старые предметы на character-роботе не удаляются. **Старая роботизированная синхронизация больше не создаёт familiar Items на character**: такие записи отмечаются как пропущенные, а уже применённые остаются защищёнными. После резервного копирования проверьте и вручную уберите ненужные старые эффекты, чтобы не оставить их одновременно на роботе и фамильяре.

AON на момент сверки присоединяет текст Vital Bond к концу Spell Delivery. В каталоге он выделен в существующую отдельную запись Vital Bond без придуманной механики; источник и оговорка сохранены.

## Владелец и роботизированный компаньон

1. Создайте владельца и **отдельного актора типа character** для робота, не NPC.
2. Откройте **Настройки модуля → SF2e Missing Tech Pets → Открыть инструменты**, выберите владельца и свяжите компаньона через Tech Pets. Оба актора должны быть доступны для редактирования.
3. Перетащите шасси из компендиума **Robot Chassis** на лист компаньона. Если допустимы два размера, настройте размер через выбор предмета либо дополнительные инструменты в настройках модуля.
4. Проверьте результат на листе компаньона. Выбирайте и меняйте улучшения в его разделе **Способности → Улучшения робота**.
5. Укажите фактическую ступень робота. **Advanced/Superior** разрешает выдачу манёвра, но переключатель **не выдаёт фиты ступени и не повышает характеристики**.

Связь сохраняется в обе стороны. Self-link, циклы, цепочки компаньонов и присвоение занятого компаньона запрещены. При открытии Tech Pets с привязанного компаньона используется профиль владельца.

Шасси из собственного компендиума можно перенести штатным drag-and-drop на отдельный character-лист. Без владельца такой актёр учитывается как самостоятельный компаньон, а не как ссылка на самого себя. Происхождение из стороннего пака остаётся пользовательским: модуль не присваивает себе право его перезаписывать.

На акторе нельзя иметь два ancestry. Конфликтующее происхождение модуль **не удаляет**: сначала проверьте его вручную.

## Собственные компендиумы

| Пак | Содержимое |
| --- | --- |
| `robot-chassis` | 5 ancestry: Agile, Imitator, Powerful, Surveillance, Tank |
| `robot-advanced-maneuvers` | 5 action: Surgical Strike, Disturbing Display, Hydraulic Flipper, Blinding Spotlight, Ram Slam |
| `robot-support` | 5 отдельных action с Support Benefit соответствующего шасси |
| `familiar-abilities` | 38 action: способности Pet / Familiar / Master из Tech Core |
| `robot-customizations` | 36 bonus feat с описаниями; 10 содержат пассивные Rule Elements |

Шасси задают нативные поля ancestry и Rule Elements: базовые модификаторы, HP, размер, скорости, чувства, обучение навыкам, traits и Strikes. Базовый класс компаньона выдаётся через GrantItem из **SF2e**-пака зависимости:

`Compendium.pf2e-animal-companions.sf-AC-Features.Item.KKOgokqHa7RjVDN6`

Без доступного класса новое неполное шасси не создаётся; прежние предметы сохраняются и показывается предупреждение.

Поддержка выдаётся вместе с шасси, манёвр — на Advanced/Superior. Действия можно открыть на нативном листе и отправить в чат. Дополнительные инструменты доступны из настроек модуля.

**Манёвры и поддержка разыгрываются вручную:** модуль не выполняет за них Strikes, Demoralize, спасброски, перемещение, длительности и условное наложение состояний. Ссылки на состояния в текстах не означают их автоматического применения.

## Imitator Chassis

До настройки у Imitator **нет сгенерированного имитируемого Strike**. Medium / 25 футов в исходном ancestry — временные значения, не выбранный вид существа; перед игрой настройте шасси.

1. Выберите Imitator, затем «Настроить Imitator».
2. Найдите живое происхождение из `sf2e.ancestries` либо животное из SF2e-пака происхождений Companion Compendia.
3. Источник должен явно задавать размер, скорости и хотя бы одну безусловную рукопашную безоружную атаку.
4. Выберите конкретную атаку и подтвердите.

Сохраняются UUID/название источника, размер, скорости и выбранная атака. Робот получает **1d4 выбранного типа урона**, unarmed, agile, finesse; чужие бонусы, черты и Rule Elements не копируются. Выбор переживает повторную синхронизацию.

Условные, вычисляемые, ranged-атаки и источники с неоднозначным размером отклоняются. Не все живые происхождения содержат подходящий Strike, поэтому **не все виды доступны**. Произвольные NPC и копирование всех особенностей существа не поддерживаются.

## Кастомизации, способности и слоты

- Для 36 кастомизаций включены собственные предметы-источники; сохранены поиск и браузер компендиумов; 38 способностей фамильяра расширены до самостоятельных Items и отдельной панели.
- Используются совместимые Item-паки SF2e. PF2e-паки, чужая явно указанная система, PF2e-ссылки в Rules и неизвестные установленной системе ключи Rule Elements отклоняются.
- Известные кастомизации разрешаются по точным ID собственного каталога, не по совпавшим именам способностей фамильяра. Для прочих поисков точный slug/identifier ищется во всех разрешённых паках **до** поиска по имени. Проверяется тип Item. Источник копируется с Rules и `flags.core.sourceId`.
- Неопределённые сторонние паки без данных о системе не считаются безопасными автоматически.
- При отсутствии источника запись остаётся в профиле; эффекты не выдумываются. Ранее применённый предмет не удаляется из-за временной недоступности источника.
- Ручная запись — только заметка и учёт слотов, не работающий Rule Element.
- Дополнительные слоты задаются точным slug в настройке slotGrantRules или флагом Item `flags.sf2e-missing-tech-pets.modificationSlots`.
- Общий slug customization сам по себе слотов не даёт. Дубли источника не начисляют слоты повторно; правило и флаг одного Item не суммируются.
- Выборы сверх доступных слотов сохраняются, но пропускаются при синхронизации. Ступень в каталоге не заменяет проверки всех игровых prerequisites.

## Сохранность данных и обновление

Синхронизация сериализуется для одного контроллера/компаньона. Повторный запуск не пересоздаёт уже применённые Items.

Удалению и замене подлежат только собственные сгенерированные предметы соответствующего controllerActorId, имеющие неизменённый контрольный снимок. Ручные предметы, другие контроллеры и изменённые пользователем копии сохраняются.

**У старых предметов может отсутствовать снимок.** Они защищены от автоматической замены даже со старой меткой модуля. После резервного копирования сравните их с новыми компендиумами. Для перехода вручную удалите только подтверждённую старую копию шасси и связанные старые действия, затем повторите выбор и синхронизацию. Не удаляйте чужие Items и не стирайте флаги массово.

Старые записи без controllerActorId распознаются только при подтверждении прежнего компаньона через lastAutomationSync; отсутствие снимка по-прежнему запрещает автоматическое удаление.

## Механик: экзокортекс

Откройте **Техно-питомцы → Механик: экзокортекс** у персонажа-механика. Сначала выберите экзокортекс через **системную особенность SF2e**. Панель распознаёт уже полученные Drone, Mine и Turret, включая несколько законно полученных вариантов. Она не выдаёт класс, посвящение, черты или дополнительный экзокортекс.

Интеграция использует существующие UUID особенностей и действий **SF2e 1.6.0**, а не раздаёт их дубликаты в своих паках. Кнопка **«Добавить недостающие системные действия в мой лист»** импортирует доступные Modify, Deploy Mine, Detonate Mine, Deploy Turret, Reposition Exocortex и Synchronized Step с сохранением источника и без повторов. Уже имеющиеся и вручную импортированные действия не заменяются и не удаляются. Системные правила можно открыть или отправить в чат.

### Дрон

- Свяжите механика с отдельным компаньоном типа **character** в «Техно-питомцах», затем перетащите шасси из компендиума Robot Chassis. Связь должна быть взаимной.
- Особенность Drone добавляет в профиль связанного компаньона **два отдельных слота только для коммерческих кастомизаций**. Кастомизации более высокой категории и ручные записи не могут их использовать. Потеря этих слотов не стирает записи профиля.
- Сохраняется стоимость командования: **одно или два действия**, с напоминанием об обычных двух или трёх действиях дрона. Панель не списывает действия и не командует токеном.
- После подтверждения ремонта/ежедневной подготовки можно восстановить ОЗ связанного дрона; после минутной аварийной перезагрузки — **1 ОЗ из 0**. Кнопки меняют только ОЗ, не переводят время, не снимают состояния и не добавляют иммунитет отключённого дрона.
- Показаны дальность и исключительность управления владельцем, напоминания о Desperate Repair, Killbot и критической специализации. Их эффекты и проверка дистанции остаются ручными.

### Мины

- Подготовленные/переносимые мины учитываются отдельно от размещённых; каждой размещённой мине можно дать название. Лимит, кости урона, радиус и лимит целей Smart Mine рассчитываются по уровню и Интеллекту.
- Можно учесть размещение, собрать все размещённые мины, создать до двух мин после десяти минут или подтвердить ежедневную подготовку с заменой всех неиспользованных мин. Размещённые мины не занимают переносимый лимит. Сбор не уничтожает избыток: если переносимый лимит превышен, разрешите это вручную.
- Взрыв выбранной мины выполняет **нативный DamageRoll SF2e** с огненным или колющим уроном и затем убирает эту мину из учёта. При ошибке броска мина сохраняется. Базовые кости масштабируются по уровню; бонусы модификаций не добавляются скрыто.
- Учёт **не** размещает объекты сцены, не измеряет расстояния, не выбирает цели, не бросает спасброски, не применяет урон и не срабатывает реакцией самостоятельно. Действие/реакция, триггер, исключения Smart Mine и Targeting Mine проверяются вручную.

### Турель

- Учитывается одна убранная/размещённая турель: текущие ОЗ, порог поломки, Твёрдость, КС механика как КД и базовые Стойкость/Рефлекс, включая вариант «Мастерство без уровня».
- Можно выбрать и сохранить одну из **шести конфигураций** с базовым типом урона, шагом дальности, признаком и группой оружия. Для смены нужно обычное время или соответствующая модификация; панель не применяет её длительность.
- При 0 ОЗ турель в учёте убирается. Подтверждение ежедневного ремонта восстанавливает все ОЗ. В конце текущего хода владельца кнопка **+5 ОЗ** убранной турели доступна однократно за этот ход. Это подтверждаемая операция, а не автоматический хук боя.
- Это запись устройства, **не автоматически созданное оружие или самостоятельный актор**. Атаки, категория и улучшения оружия, общий штраф множественной атаки, цели и укрытие разрешаются через системный лист. Сломанная турель не атакует; панель не предлагает отдельную атаку в обход штрафа владельца.

### Взаимодействие с классом механика

Панель отличает полноценный класс от **Mechanic Dedication**: само посвящение не открывает Modify. Mobile Exocortex, Remote Mods, Enduring Mods, Manifold Mods и Instant Mods учитываются в подсказках, дальностях и доступном импорте действий. Архетипный Remote Mods не получает классовое увеличение дальности на 15-м уровне. Эти подсказки не применяют Rule Elements модификаций, длительности, ежедневный выбор цели и ограничение раз в раунд автоматически.

Состояние хранится в `flags.sf2e-missing-tech-pets.exocortex`, отдельно от прежних профилей роботов и фамильяров. Операции одного владельца ставятся в очередь в текущем клиенте. Между разными клиентами транзакционной блокировки нет: для учёта устройств используйте один управляющий клиент.

## API

```js
const api = game.modules.get("sf2e-missing-tech-pets").api;
api.open(actor);
await api.linkActors(owner, companion);
await api.syncAutomation(owner);
```

Сохранены `open(actor?)`, `searchFamiliarItems(actor?, query?)`, `getRobotData(actor)`, `setRobotData(actor, data)`, `getModificationSlots(actor)`, `getLinkedCompanion(actor)`, `resolveImportTarget(actor, item)`, `addCompendiumItem(actor, item)`, `syncAutomation(actor)`, `registerSlotGrant(slug, slots = 1)`, `openPack(key, actor?)`.

Добавлен `linkActors(owner, companion)`; null вместо companion разрывает связь. setRobotData проверяет ссылки; занятый компаньон сначала освобождается от старой связи. syncAutomation возвращает `{ applied, skipped, reason? }`: **applied — число применённых/сохранённых Items, не автоматически исполненных игровых эффектов**.

Дополнительный API фамильяров (отдельно от связи роботов):

```js
await api.openFamiliar(owner); // также принимает familiar
const familiar = await api.createFamiliar(owner, "wis");
await api.linkFamiliar(owner, familiar, "wis");
await api.syncFamiliarAbilities(owner, familiar, ["flier", "tough"]);
```

`createFamiliar` требует отсутствие другого связанного фамильяра; не выдаёт фит владельцу. `linkFamiliar` не захватывает занятого актора. `syncFamiliarAbilities` возвращает `{created, removed, protected}` и отклоняет невалидный набор с локализованной ошибкой. Эти методы также требуют активную обязательную зависимость.

Дополнительный API экзокортекса (прежние методы сохранены):

```js
await api.openExocortex(owner);
const state = api.getExocortexData(owner); // Отдельный нормализованный снимок.
await api.updateExocortex(owner, "mine-craft");
await api.installExocortexActions(owner);
```

Операции `updateExocortex`: `mine-daily` (`confirmed: true`), `mine-craft`, `mine-deploy` (`label`), `mine-collect`, `mine-detonate` (`id`, `damageType: "fire" | "piercing"`), `turret-array` (`array`), `turret-deploy` (переключение), `turret-hp` (`hp`), `turret-repair` (`confirmed: true`), `turret-recover`, `drone-command` (`actions: 1 | 2`). Аргументы передаются третьим параметром. Это явный учёт, не отмена игровой стоимости. `getModificationSlots` дополнительно возвращает `generalTotal` и `commercialSlots`; поле `free` включает ограниченные слоты и не разрешает расходовать их на любую категорию.

## Разработка и проверки

Код запускается как ES modules без сборки JS. Для разработки: Node.js 22+ и `npm install`.

```sh
npm run build:packs
npm run check
npm test
```

`data/robot-chassis.json` и `scripts/item-sources.mjs` — источник предметов. Для фамильяров источники — `data/familiar-abilities.json` и `scripts/familiar-sources.mjs`. Источники кастомизаций — `data/robot-customizations.json` и `scripts/customization-sources.mjs`. Сборка обновляет пять packs/src/, текстовые .db и готовые LevelDB-каталоги. Манифест загружает **LevelDB**; .db оставлены как проверяемые текстовые снимки, не рабочие пути v14.

Воспроизводимость проверяется по документам/ID, не двоичному совпадению служебных файлов LevelDB. Сборщик сначала компилирует во временную папку и извлекает документы обратно, затем заменяет свой готовый пак.

Подробности: [изменения](CHANGELOG.md), [выпуск релизов через GitHub Desktop](docs/RELEASING.md).
