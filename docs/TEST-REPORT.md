# Отчёт о проверках 0.12.0

Это три разных уровня проверки: статические файлы, тесты с подменой API и локальный браузерный макет. Ни один из них не является запуском мира Foundry.

## Статика

`npm run check`: **66 JSON**, **12 файлов .mjs**, **149 одинаковых ключей EN/RU**. Проверены `node --check`, разбор JSON, паритет языков и наличие буквальных t("...") во всех scripts/*.mjs.

Манифест: Foundry minimum 14.361 / verified 14 / maximum 14; sf2e >=1.6.0; обязательный pf2e-animal-companions >=7.6.3. Набор 11 SF2e-паков зависимости сохраняется; проверяется по ранее изученному манифесту 7.7.3 и fixtures. В этой итерации минимальная версия не повышалась.

## Данные и реальные файлы компендиумов

Четыре SF2e Item-пака содержат **53 документа**: 5 шасси, 5 манёвров, 5 поддержек и 38 способностей фамильяра.

Официальный Foundry CLI компилирует настоящие LevelDB, затем извлекает их обратно. Проверены число и точное содержимое документов, стабильные уникальные ID/slugs, типы Item, sourceId, JSONL-снимки и packs/src. Рабочие пути манифеста указывают на LevelDB-каталоги, не старые NeDB .db.

Повторная сборка всех четырёх паков воспроизводит JSON, JSONL и ID. Двоичные служебные файлы LevelDB не обязаны совпадать. Открытие через CLI — не доказательство открытия компендиума в Foundry v14.

## Автоматические тесты: 58 / 58

`npm test` запускает:

- **10** тестов манифеста, SF2e-источников, предметов роботов, LevelDB и повторной сборки;
- **18** тестов фамильяров: 38 полных источников, десять проверенных пассивных схем RE, стоимость Familiar Focus, нативная связь, создание правильного типа Actor, защита занятого актора, зависимость/система/права, лимиты, идемпотентность, сериализация, prerequisites, врождённые способности, пользовательские изменения, отсутствующий источник, отказ создания, сохранность старого профиля;
- **30** mock-тестов интеграции: прежние сценарии роботов и API, фильтрация PF2e, drag-and-drop/sourceId, очистка по контроллеру/снимку, слот-учёт, импорт familiar Items на правильного актора и сохранность прежних familiar-предметов на роботе.

Mocks не запускают подготовку характеристик, Rule Elements, миграции Actor/Item и системные листы.

## Локальная проверка Chromium

Проверен настоящий DOM новой панели с реальным кодом модуля, но подставными DialogV2, Actor, Item и game:

- 38 строк и русские подписи;
- чтение нативной характеристики владельца;
- поиск без изменения выбора;
- выбор двух способностей и сохранение;
- явная отметка врождённой способности и блокировка снятия;
- открытие листа/Item и отправка в чат — вызовы соответствующих mock-методов;
- одно окно после повторного открытия, блочная разметка описаний, отсутствие горизонтального переполнения;
- отсутствие ошибок JavaScript и уведомлений об ошибке.

Это браузерный smoke-тест макета, **не Foundry runtime**. Системные стили и реальные ограничения окна Foundry здесь не проверены.

## Что НЕ проверено в настоящем Foundry

Нет запущенного игрового мира Foundry v14 + SF2e 1.6.0 + Companion Compendia. Не подтверждены:

- установка/активация в мире и открытие четырёх паков системным интерфейсом;
- подготовка HP/КД/спасбросков/навыков фамильяра системой;
- фактическое применение десяти пассивных Rule Elements;
- права игроков при реальном Actor.create, штатный drag-and-drop и чат;
- точная высота/прокрутка диалога под темами Foundry;
- совместимость со сторонними модулями и обновлениями системы.

## Игровой чек-лист перед основной кампанией

1. Сделать резервную копию; использовать тестовый мир.
2. Активировать обязательную зависимость >=7.6.3 и модуль 0.12.0.
3. Открыть четыре компендиума, убедиться в наличии 5/5/5/38 Items.
4. Создать familiar через панель владельца; проверить system.master, выбранную характеристику и права.
5. Сравнить нативные показатели с владельцем; затем проверить Flier, Darkvision и Tough на нескольких уровнях. Не допустить двойного Tough.
6. Выбрать 2 способности, заменить одну и повторить сохранение; проверить отсутствие копий и сохранение ID оставшейся.
7. Пометить Flier врождённой, проверить лимит и невозможность снятия ежедневным набором.
8. Отредактировать описание одного созданного Item; сменить набор и убедиться, что изменённая копия осталась.
9. Перетащить способность из собственного пака на native familiar: она должна быть видна на листе, учитываться в панели и оставаться пользовательской.
10. Проверить prerequisites Construct/Tough, Kinspeech/Speech/уровень; другие условия всё равно сверять вручную.
11. Проверить переход со старых записей: только явное сохранение создаёт новые Items; прежние профиль и предметы не удаляются.
12. Выполнить прежний чек-лист роботов из TEST-REPORT-0.11.0.md.

## Ограничения

28 способностей содержат описание для ручного применения; выбор вариантов, ресурсы, эффекты владельца и повторные Skilled не автоматизированы. Панель не выдаёт разрешающий фит владельцу и не создаёт его системный счётчик: если его значение 0, панель показывает предусмотренные правилами 2, но нативный лист может продолжать показывать свой 0 до настройки подходящего системного предмета. Явный лимит тоже действует только в панели. Это не изменение подготовленных данных системы.
