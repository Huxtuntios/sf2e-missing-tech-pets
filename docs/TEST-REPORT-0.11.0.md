# Отчёт о проверках 0.11.0

## Статические проверки

Команда: `npm run check`.

- 8 файлов .mjs: `node --check` без ошибок.
- 28 JSON-файлов: корректный JSON.
- Локализации EN/RU: одинаковые **109 ключей**; все буквальные вызовы t("...") в main.mjs имеют строки.
- Манифест: id/version, Foundry v14, SF2e >=1.6.0, обязательная зависимость >=7.6.3 и три собственных SF2e Item-пака.
- Все 11 используемых SF-ключей точно совпадают со снимком проверенного манифеста Companion Compendia 7.7.3. Минимум 7.6.3 также изучен при аудите, не повышен.
- Реальные нативные поля ancestry и пути SF2e сверены по исходникам системы, не только по JSON-примеру.
- Проверено, что публичные методы API сохранены; добавление linkActors не требует миграции вызовов старых методов.

## Автоматические тесты: 38 / 38

Команда: `npm test`. Node.js запускает файлы последовательно, чтобы сборка паков не пересекалась с чтением тестовых данных.

### 10 тестов данных и паков

Манифест и dependency; точные SF-ключи; совпадение 15 Items с фабриками/каталогом/JSONL; стабильные уникальные ID и типы; поля/пути ancestry; реальный Bird/Ape как источники Imitator; отказ от неподдерживаемых источников; выбор размера; честное обозначение ручных действий; обратное извлечение LevelDB; повторная воспроизводимая сборка.

### 28 mock-тестов реального кода модуля

- API/интеграция не запускаются без обязательной зависимости или в PF2e.
- Каждый из 11 отсутствующих SF-паков обнаруживается отдельно; проверяется список отсутствующих паков, а не реальное DOM-состояние кнопок.
- Фильтрация PF2e, чужой системы, неопределённых сторонних паков, PF2e UUID и неизвестных ключей RE.
- Повторная и параллельная синхронизация без дубликатов/лишних записей Items.
- Замена шасси на месте, выдача манёвра только на разрешённой ступени.
- Сохранение ручных действий, изменённых Items, старых Items без снимка и предметов другого контроллера.
- Обработка отсутствующего/не-character компаньона, self-link, циклов, занятого компаньона и обратной связи API.
- Сохранение прежнего Item и записи при исчезновении источника кастомизации.
- Слоты: точный slug, защита от повторного начисления, отсутствие бонуса от общего customization, пропуск превышения лимита.
- Ручные записи не превращаются в выдуманную механику.
- Нативный sourceId, самостоятельный компаньон, повторная обработка drag-and-drop.
- Ancestry импортируется компаньону, конфликтующие ancestry не удаляются.
- Точный slug имеет приоритет над совпадением имени в другом паке.
- Шасси другого контроллера не получает второе ancestry.
- Legacy распознаётся только с подтверждением, но без снимка не удаляется.
- Собственные паки имеют локальный fallback, не отменяющий обязательную зависимость.
- Размер, выбор Imitator и ID сохраняются; после смены шасси повторный sync не пишет Item заново.
- Регистрируется пункт заголовка ActorSheetV2 с локализованной подписью.
- Без доступного класса компаньона прежнее шасси/действия сохраняются.

Mocks подменяют API документов, коллекций, Hooks и диалогов. Они **не исполняют** реальные Rule Elements, броски, DOM и систему Foundry.

## Проверка компендиумов и воспроизводимости

`npm run build:packs` создаёт три LevelDB-пака по пять предметов. Каждый готовый пак извлечён официальным CLI; все 15 документов совпали с JSON-источниками. Повторная сборка сохраняет логическое содержимое, JSON/JSONL и ID. Двоичная идентичность внутренних журналов LevelDB не требуется.

Это проверка реальных файлов LevelDB, но **не** открытие/миграция компендиумов в Foundry. В архив включены готовые базы, не только исходники.

## Что не проверялось в runtime

**Настоящий Foundry VTT v14 + SF2e 1.6.0 + активный Companion Compendia не запускался.** Не подтверждены игровым тестом: исполнение RE, итоговые характеристики, Strikes, штатные выборы, отображение окон, чат, открытие паков в мире и совместная работа нескольких клиентов.

## Чек-лист первого игрового запуска

1. Сделать резервную копию и открыть копию мира SF2e.
2. Проверить установку/активацию обязательной зависимости и трёх собственных паков.
3. Открыть каждый пак, проверить по пять Items и ссылки на состояния/класс.
4. Создать отдельные character-акторы владельца и робота, связать их через Tech Pets.
5. На чистом роботе проверить пять шасси: базовый класс, HP/размер/скорости/чувства/навыки/traits и Strikes без двойных бонусов.
6. Проверить выбор размера и Imitator с конкретным Bird/Ape, перезапуск мира и повторную синхронизацию.
7. Проверить Commercial и Advanced: поддержку/манёвр, отправку в чат; последствия разыграть вручную.
8. Изменить собственный Item вручную: повторный sync должен сохранить его и предупредить.
9. Проверить чужое ancestry, пользовательский манёвр, старый Item без снимка, разрыв/смену связи и отсутствие источника.
10. Проверить кастомизацию с реальным источником и без него, слоты/дубли и штатный drag-and-drop.
11. Проверить русский/английский интерфейс, пункт ActorSheetV2 и описания в DialogV2.
12. Только после успешного игрового теста переносить обновление в основной мир.
